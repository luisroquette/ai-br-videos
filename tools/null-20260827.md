# null

`null` é um pacote Go que resolve um problema chato: campos nuláveis em JSON. Em Go, zero value de `int` é `0`, de `string` é `""`, e isso confunde quando a API precisa distinguir "ausente" de "zero". O pacote oferece tipos como `null.Int`, `null.String`, `null.Bool`, `null.Time` e variações, que implementam `json.Marshaler` e `json.Unmarshaler` corretamente. Também tem `null.NewInt(5, true)` para setar valor + valid, e métodos `.Valid` para checar se o campo veio na payload.

## Por que importa

Sem isso, você acaba escrevendo ponteiros (`*int`) e um monte de boilerplate para marshaling condicional. Com `null`, o contrato da API fica explícito no struct: `Price null.Int` deixa claro que o campo pode ser `null` e que `0` é um valor legítimo. Menos bugs de serialização, menos código de validação manual. Para quem trabalha com APIs externas ou banco de dados com colunas `NULL`, é uma camada de segurança que vale a pena.

## Como começar

1. Adicione: `go get gopkg.in/guregu/null.v4` (ou `null.v3` se estiver em projeto legado).
2. Troque campos `int`/`string` por `null.Int`/`null.String` nos structs de request/response.
3. Use `.Valid` para decidir se o campo foi enviado, e `.ValueOrZero()` para fallback.
4. Para scan de banco, o pacote já implementa `sql.Scanner` — funciona direto com `database/sql`.

Não resolve tudo, mas elimina uma classe inteira de bugs de borda. Se você já perdeu tempo debugando `0` vs `null` em JSON, esse pacote é o remendo certo.
